# Directory Structure

> How backend code is organized in this project.

---

## Overview

The backend follows a layered architecture with clear separation between handler → service → repository. The project uses Go with Ent ORM for database access and Gin as the HTTP framework. Dependency injection is managed via `wire`.

---

## Directory Layout

```
backend/
├── cmd/
│   ├── server/              # Main application entry point
│   │   ├── main.go          # Entry point, calls setup.Run()
│   │   ├── wire.go          # Wire provider set definitions
│   │   └── wire_gen.go      # Generated dependency injection code
│   └── <tool>/              # Additional CLI tools (optional)
├── ent/
│   ├── schema/              # Ent schema definitions (run `go generate` after changes)
│   │   ├── mixins/          # Reusable schema mixins (TimeMixin, SoftDeleteMixin)
│   │   └── *.go             # Entity schema files
│   ├── generate.go          # Ent code generation directive
│   └── <generated>/         # Auto-generated Ent code (do not edit manually)
├── internal/
│   ├── config/              # Application configuration loading and validation
│   ├── domain/              # Domain constants, enums, status values shared across layers
│   ├── handler/             # HTTP handlers (Gin handlers)
│   │   ├── admin/           # Admin-specific handlers
│   │   ├── dto/             # Data transfer objects and mappers
│   │   └── *.go             # User-facing and gateway handlers
│   ├── integration/         # End-to-end integration tests
│   ├── middleware/          # Standalone middleware components
│   ├── model/               # Domain models (non-Ent types)
│   ├── pkg/                 # Shared utility packages
│   │   ├── errors/          # Application error types and HTTP mapping
│   │   ├── logger/          # Structured logging
│   │   ├── pagination/      # Pagination helpers
│   │   ├── response/        # HTTP response formatting
│   │   └── ...              # Other cross-cutting packages
│   ├── repository/          # Data access layer (Ent + raw SQL)
│   ├── server/              # HTTP server setup and routing
│   │   ├── middleware/      # Server-level middleware (auth, CORS, recovery)
│   │   ├── routes/          # Route definitions grouped by concern
│   │   ├── http.go          # Server initialization
│   │   └── router.go        # Gin router setup
│   ├── service/             # Business logic (must NOT import repository)
│   ├── setup/               # Application bootstrap and wiring
│   ├── testutil/            # Test helpers and fixtures
│   └── util/                # Internal utility packages
├── migrations/              # SQL migration files (authoritative schema source)
├── resources/               # Static resources (templates, seed data)
├── config.yaml             # Application configuration
└── Makefile                # Build commands
```

## Module Organization

### Entry Point (`cmd/server/`)

The application entry point wires dependencies and starts the server.

- `main.go` — calls `setup.Run()` to bootstrap the application
- `wire.go` — defines Wire provider sets for dependency injection
- `wire_gen.go` — auto-generated by `wire`; do not edit manually

### Handler Layer (`internal/handler/`)

HTTP handlers receive requests, parse input, delegate to services, and format responses. They must NOT import repository.

- One file per resource/domain (e.g., `account_handler.go`, `user_handler.go`)
- Admin handlers live in `handler/admin/`
- Gateway/proxy handlers live at the handler root level
- Request/response DTOs defined in `handler/dto/` or in the handler file itself
- A `Handlers` struct aggregates all handler instances for wiring
- Use Gin context for request parsing and response writing

### Service Layer (`internal/service/`)

Business logic lives here. Services must NOT import repository — they only know interfaces.

- One file per resource/domain (e.g., `account_service.go`, `user_service.go`)
- Define repository interfaces in the service package (e.g., `account_repo.go` interface)
- Request/response types are typically defined in the service file
- Use `pkg/errors` for application errors
- Cache invalidation ports and interfaces live alongside the service

### Repository Layer (`internal/repository/`)

Data access implementation. Uses Ent ORM for type-safe queries and raw SQL for complex operations.

- One file per resource (e.g., `account_repo.go`, `user_repo.go`)
- Implement service-defined repository interfaces
- Use Ent generated types from `ent/`
- For batch operations, complex aggregation, or JSONB manipulation: use raw SQL
- Include `_test.go` and `_integration_test.go` suffix for tests
- Cache implementations (Redis, in-memory) live alongside repositories

### Domain Layer (`internal/domain/`)

Domain constants and enums used across layers.

- Status values, role constants, platform identifiers
- Shared constants that multiple layers need to agree on

### Server Layer (`internal/server/`)

HTTP server setup, route registration, and middleware wiring.

- `http.go` — server initialization and lifecycle
- `router.go` — Gin engine setup
- `routes/` — route definitions grouped by concern (e.g., `auth.go`, `admin.go`, `gateway.go`)
- `middleware/` — server-level middleware (JWT auth, API key auth, CORS, recovery, logging)

### Config Layer (`internal/config/`)

Application configuration loading, validation, and environment variable handling.

- `config.go` — config struct definitions and loading logic
- `wire.go` — Wire provider for config

### Setup Layer (`internal/setup/`)

Application bootstrap — ties together all layers and starts the server.

- `setup.go` — main bootstrap logic
- `handler.go` — handler assembly
- `cli.go` — CLI command definitions (if any)

### Shared Packages (`internal/pkg/`)

Cross-cutting concerns shared across layers:

| Package | Purpose |
|---------|---------|
| `errors/` | Application error types and HTTP status mapping |
| `logger/` | Structured logging configuration and helpers |
| `pagination/` | Pagination params and result types |
| `response/` | HTTP response formatting helpers |
| Platform-specific packages | Protocol helpers for external APIs |

## Naming Conventions

| Type | Convention | Example |
|------|------------|---------|
| Schema files | snake_case | `account.go`, `user.go` |
| Handler files | snake_case | `account_handler.go` |
| Service files | snake_case | `account_service.go` |
| Repository files | snake_case | `account_repo.go` |
| Route files | snake_case | `auth.go`, `admin.go` |
| Middleware files | snake_case | `jwt_auth.go`, `cors.go` |
| Test files | `*_test.go`, `*_integration_test.go` | `account_repo_test.go` |
| Package name | snake_case | `repository`, `service` |
| Ent generated | PascalCase | `dbaccount.Account` |

## Module Dependency Rules

```
handler → service → repository → ent
                           ↓
                        database
```

**Strict rules:**
1. `service` must NOT import `repository` (architectural boundary enforced by golangci-lint)
2. `handler` must NOT import `repository`
3. `handler` can import `service` and `pkg/errors`
4. `repository` can import `service` for interface types and cache ports
5. `server` can import `handler`, `middleware`, and `routes`
6. `setup` can import all layers for wiring

## Examples

### Creating a new entity

1. Define schema in `ent/schema/<entity>.go`
2. Create migration in `migrations/XXX_description.sql`
3. Run `go generate ./ent` to generate code
4. Define repository interface in `internal/service/<entity>_repo.go`
5. Implement repository in `internal/repository/<entity>_repo.go`
6. Implement service in `internal/service/<entity>_service.go`
7. Implement handler in `internal/handler/<entity>_handler.go` (or `admin/` for admin-only)
8. Add route in `internal/server/routes/`
9. Wire handler in `internal/handler/wire.go`
10. Wire service/repository in `internal/service/wire.go` and `internal/repository/wire.go`

### Key files to follow

- Schema: `ent/schema/account.go`
- Mixin: `ent/schema/mixins/soft_delete.go`
- Service interface: `internal/service/account_service.go`
- Repository implementation: `internal/repository/account_repo.go`
- Handler: `internal/handler/admin/account_handler.go`
- Route: `internal/server/routes/admin.go`
- Wire: `cmd/server/wire.go`
